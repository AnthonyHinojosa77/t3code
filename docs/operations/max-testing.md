# MAX phone and computer walkthrough and deployed smoke

Run `corepack pnpm e2e:max` for every PR touching MAX, web, or the gateway. It builds the production web app, starts an isolated loopback gateway and companion, and drives the real T3 engine at `127.0.0.1:3773` with headless Chromium. The default command runs four passes from one build: a dark phone pass at 390×844 (scale 3, touch) that spends one real council round, then three no-round passes that reuse the build: light phone at 360×780, dark computer at 1440×900 and light computer at 1440×900 (scale 2, mouse and keyboard, no touch). Run `corepack pnpm e2e:max -- --skip-build` only when this checkout's web build is already current.

Prerequisites: `corepack pnpm install --frozen-lockfile`, Node matching the root manifest, a running T3 engine, `~/.t3/bin/t3`, and `PLAYWRIGHT_BROWSERS_PATH` pointing to already installed Playwright Chromium. The command does not download browsers. The CLI must support `auth session issue --json` and `auth session revoke`. Normal production builds also require the repository's generated license notices; if using the manager's existing `.generated/` cache, copy it into this checkout rather than linking or writing to the source.

## Flags

- `--single-scheme` runs one pass instead of the four. Combine with `--light` for the light theme, `--desktop` for the 1440×900 computer profile, and `--no-round` to spend no model turns. A `--light` or `--desktop` or `--no-round` run is always a single pass.
- `--research-round` sends a web-search prompt in the real round and requires an auto-mode model.
- `--evidence <dir>` records a video of the whole pass (so every page turn is on film) and copies the run's screenshots, video and summary to `<dir>/<scheme>-<device>-<viewport>/`.

## What one pass covers

The local test registers only `owner@example.com`, signs out and back in, and waits for council bootstrap. Then, in order:

1. **Theme.** It switches to old MAX's light mode with the header toggle, reloads, and checks the chat window renders the Windows 98 chrome-gray surface (`rgb(192, 192, 192)`), so the contrast gates below run on a real light theme. A light pass stays light for every later step; a dark pass toggles back and checks dark survives a reload. The sign-in screen has the same toggle.
2. **Model window.** Everything about models lives behind the composer's `Choose models` button: it opens the window, chooses two contenders and a synthesizer, sets low effort, opens the traits menu, opens Manage templates, checks provider usage bars against engine snapshots, and closes the window; the button then reads `2 models · judge set`.
3. **Seeded round.** Before the companion starts, the run writes one finished round into its temporary council database: three contenders (two answers that finished three and nine seconds in, one failure) and a structured synthesis. From the side panel (a drawer on phones, docked on computers) it opens that round and checks the page order is first finisher, second finisher, failure, synthesis; the position reads `1 of 4`; then it turns every page by a real touch swipe through Chromium's gesture recognizer (phone) or a mouse drag (computer), by keyboard (arrows, Home), by the previous/next buttons and by clicking the peeking page edge. It checks the failed page shows its error after the answers and before the synthesis, that the synthesis page shows the verdict and is last, that each page keeps its own scroll position across turns, and that the order is the same after a reload.
4. **Smoothness.** During the touch, mouse and keyboard turns a `requestAnimationFrame` sampler records frame times for 900 ms. A pass fails if any frame is longer than 80 ms or more than two frames exceed 34 ms. The raw numbers are in `summary.json` under `pageTurns`; the gate is `pageTurnSmoothness`.
5. **Real round** (dark phone pass only). It attaches a 1×1 PNG through the plus button and sends “Reply with exactly one word: ready” to the two cheap models (Claude Haiku 5.5 and GPT-6 Luna preferred; it fails if two are unavailable). It checks the request carried one pending upload per contender with distinct ids, that two upload POSTs crossed the gateway, that the user turn lists the file, the thinking state's `n of 2 answered` progress when a model has not finished yet, that the first model to finish (by `finishedAt`) is the front page and stays in front as the other arrives, that the synthesis is the last of three pages, that each contender thread's first user message holds the attachment (from the engine's projection), that the coordinator archived every finished thread with a readable engine projection, Agent continuation from the front page (which unarchives only that thread), a real one-word reply in the restored thread (“Reply with exactly one word: restored”), return to the same round, reload persistence with the same order, and reopening from the side panel.
6. **Agent mode.** The mode switch, the thread view's theme (MAX's branded dark theme, or T3's light theme in a light pass), the return to Council, a session reload, and the explicit appearance preference check (a removed preference falls back to dark on first visit; the run's own scheme is restored afterwards).
7. **Viewports.** Without reloading it resizes through 360×780, 390×844, 430×932, 844×390 (landscape phone), 768×1024 and 1440×900. At each size it checks the panel is a drawer below 768 px and docked from 768 px, runs the gates on the home, the open panel, the seeded round's pages (with the Send button inside the viewport) and the model picker, and saves a screenshot of each.
8. **Sign out.**

Each run uses temporary auth/council databases, template directory, a random tunnel secret and a separate companion token file. It issues one one-hour session and supplies that token to its companion to avoid the companion's normal seven-day renewal window renewing a short-lived test token. After stopping the temporary companion, teardown reads only its temporary council database, interrupts any unfinished test turns, archives every created thread via EngineClient (already-archived threads count as success), and records the ids and archive results in the summary. The exact session is revoked at teardown. The live token file, live companion service and engine process are never changed. SIGINT/SIGTERM stop the processes this command owns and revoke its session; SIGKILL cannot run cleanup.

Artifacts go to `artifacts/e2e-max/<UTC timestamp>/`: numbered step screenshots, named state screenshots, `summary.json`, `console.json`, and `network-failures.json`. They are ignored by Git and may contain private UI content from existing threads: share only after inspecting/redacting. Request query strings and test credentials are redacted in diagnostic logs; cookies and authorization headers are never recorded. A failed step saves a screenshot and returns nonzero. Layout/console/network gates accumulate so the report can show multiple defects in one walkthrough.

Every screenshot step checks visible viewport text against its composited ancestor background using WCAG AA contrast: 4.5:1 normally, 3:1 for text at least 24px or bold text at least 18.66px. Disabled controls and placeholders use a documented 3:1 floor. Open popover, select, menu and dialog panels must have background alpha of at least 0.95. Finite entrance transitions finish before measurement; infinite status pulses keep running. Every visited screen is checked for horizontal overflow, truncated MAX wordmarks, and primary controls smaller than 40 CSS pixels in either dimension on the phone profile (28 CSS pixels on the computer profile, where T3's own header controls are 28 px and a pointer is precise). Primary controls include auth submission, mode switching, the model button and pickers, Council return, Send, the plus and mic buttons, page navigation, Continue in Agent Mode, Copy, Cancel, the side panel's rows and New chat, template management, and role/traits/project selectors. Uncaught page errors, console errors and failed same-origin requests fail the run; the sole allowlisted response is the anonymous `/api/auth/me` 401 used to display the login form (including Chromium's matching resource-error console line). Long tasks over 200 ms are recorded across navigations; more than ten fails the run. This initial budget allows cold production bootstrap across registration, login and reload, but rejects repeated stalls; it is a reproducible regression signal, not proof of real-phone frame rate.

Run after every merge/redeploy:

```sh
corepack pnpm smoke:max -- --url https://max-gateway-production.up.railway.app
corepack pnpm smoke:max -- --url https://max-gateway-production.up.railway.app --expect-commit <full-git-sha>
```

Smoke is anonymous and read-only: health, unauthenticated session/descriptor, denied council/environment/WebSocket access, index-referenced JavaScript/CSS, and manifest/icons. It never registers or signs in. `--expect-commit` additionally matches `/__max/version` to Railway's `RAILWAY_GIT_COMMIT_SHA`; a pre-deployment gateway cannot pass that check. Every row prints PASS/FAIL and any failure exits nonzero. Neither command deploys, restarts the engine, or repairs defects it finds.

The scripts live in `e2e/max/` to keep complete-stack tests separate from component/browser tests. They resolve the web package's existing Playwright and gateway's existing WebSocket dependency. Keep the real council-round assertions and existing steps; do not add fake requests or placeholder passing steps. The seeded round is data the gateway serves exactly as it would a finished round; it never stands in for the real-round assertions. No additional console errors or HTTP failures are allowlisted. At logout the harness rejects any new authenticated request; cancellation of a request that started before logout is recorded separately in `cancelledAtLogout`. Deliberate reloads likewise record cancellations of requests that were active before, or started during, the reload in `cancelledAtReload` (the tracing exporter can fire a batch in that window); HTTP failures remain failures. MAX closes the request transport and stops its tracing exporter before revoking the session.

Finished council threads are archived best effort after observation stops. Startup retries archival for terminal rounds without an archive timestamp; successful archives are recorded per answer. Continue in Agent Mode records a durable exemption from future council archival. Archive failures are logged without provider errors or credentials and retried on the next companion start.

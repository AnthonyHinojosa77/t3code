# MAX phone walkthrough and deployed smoke

Run `corepack pnpm e2e:max` for every PR touching MAX, web, or the gateway. It builds the production web app, starts an isolated loopback gateway and companion, and drives the real T3 engine at `127.0.0.1:3773` with headless Chromium with scale 3 and touch/mobile enabled. The default command runs dark emulation at 390×844 followed by light emulation at 360×780; both include a 360×780 layout pass. Run `corepack pnpm e2e:max -- --skip-build` only when this checkout's web build is already current.

Prerequisites: `corepack pnpm install --frozen-lockfile`, Node matching the root manifest, a running T3 engine, `~/.t3/bin/t3`, and `PLAYWRIGHT_BROWSERS_PATH` pointing to already installed Playwright Chromium. The command does not download browsers. The CLI must support `auth session issue --json` and `auth session revoke`. Normal production builds also require the repository's generated license notices; if using the manager's existing `.generated/` cache, copy it into this checkout rather than linking or writing to the source.

The default run sends one real council round (three provider turns) using two cheap models reported ready by the engine. Prefer Claude Haiku 5.5 and GPT-6 Luna; fail if two cheap models are unavailable. It verifies completed contender text and display names, completed structured or fallback synthesis, Agent continuation, return to the same round, reload persistence, and reopening from Recent rounds. Only the dark pass sends a real round; the light pass uses `--no-round`. For isolated iteration, `--light --no-round` runs only light emulation, and `--single-scheme` runs only dark emulation. `--no-round` skips model use and runs at 360×780.

The local test registers only `owner@example.com`, signs out and back in, waits for council bootstrap, chooses two contenders and a synthesizer, checks provider usage against engine snapshots, opens the Agent new-thread view without sending, returns to Council, reloads the session, and signs out. Only the real-round steps send a prompt: “Reply with exactly one word: ready”. The Agent landing steps never send. A real engine with an existing project and two selectable models is required. Unsupported provider usage is recorded as skipped only when the engine snapshot reports no windows.

Each run uses temporary auth/council databases, template directory, a random tunnel secret and a separate companion token file. It issues one one-hour session and supplies that token to its companion to avoid the companion's normal seven-day renewal window renewing a short-lived test token. After stopping the temporary companion, teardown reads only its temporary council database, interrupts any unfinished test turns, archives every created thread via EngineClient, and records the ids and archive results in the summary. The exact session is revoked at teardown. The live token file, live companion service and engine process are never changed. SIGINT/SIGTERM stop the processes this command owns and revoke its session; SIGKILL cannot run cleanup.

Artifacts go to `artifacts/e2e-max/<UTC timestamp>/`: numbered step screenshots, `summary.json`, `console.json`, and `network-failures.json`. They are ignored by Git and may contain private UI content from existing threads: share only after inspecting/redacting. Request query strings and test credentials are redacted in diagnostic logs; cookies and authorization headers are never recorded. A failed step saves a screenshot and returns nonzero. Layout/console/network gates accumulate so the report can show multiple defects in one walkthrough.

Every screenshot step checks visible viewport text against its composited ancestor background using WCAG AA contrast: 4.5:1 normally, 3:1 for text at least 24px or bold text at least 18.66px. Disabled controls and placeholders use a documented 3:1 floor. Open popover, select, menu and dialog panels must have background alpha of at least 0.95. Finite entrance transitions finish before measurement; infinite status pulses keep running. Completed answers and synthesis are scrolled into view for additional contrast checks. The run also opens Traits and Manage templates and verifies that an explicit light appearance survives reload in Agent mode before restoring the default. Every visited screen is checked for horizontal overflow, truncated MAX wordmarks, and primary buttons smaller than 40 CSS pixels in either dimension. Primary controls include auth submission, mode switching, model pickers, Council return, Send, Continue in Agent Mode, Copy, Cancel, New question, template management, and role/traits/project selectors. Uncaught page errors, console errors and failed same-origin requests fail the run; the sole allowlisted response is the anonymous `/api/auth/me` 401 used to display the login form (including Chromium's matching resource-error console line). Long tasks over 200 ms are recorded across navigations; more than ten fails the run. This initial budget allows cold production bootstrap across registration, login and reload, but rejects repeated stalls; it is a reproducible regression signal, not proof of real-phone frame rate.

Run after every merge/redeploy:

```sh
corepack pnpm smoke:max -- --url https://max-gateway-production.up.railway.app
corepack pnpm smoke:max -- --url https://max-gateway-production.up.railway.app --expect-commit <full-git-sha>
```

Smoke is anonymous and read-only: health, unauthenticated session/descriptor, denied council/environment/WebSocket access, index-referenced JavaScript/CSS, and manifest/icons. It never registers or signs in. `--expect-commit` additionally matches `/__max/version` to Railway's `RAILWAY_GIT_COMMIT_SHA`; a pre-deployment gateway cannot pass that check. Every row prints PASS/FAIL and any failure exits nonzero. Neither command deploys, restarts the engine, or repairs defects it finds.

The scripts live in `e2e/max/` to keep complete-stack tests separate from component/browser tests. They resolve the web package's existing Playwright and gateway's existing WebSocket dependency. Keep the real council-round assertions and existing steps; do not add fake requests or placeholder passing steps. No additional console or network errors are allowlisted.

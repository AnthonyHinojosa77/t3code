## Reading the evidence

- **Present** means the source implements the named behavior; it does not mean it was run. **Partial** means only part is implemented. **Regressed** means old MAX has a reachable behavior that this Council surface lacks. **Missing** means a required behavior has no implementation found. **Deliberately omitted** requires a recorded scope decision; it is not inferred from absence. **Not yet due** marks Plan 2 work.
- All runtime behavior is **UNVERIFIED (static analysis only)**: no models, local engine, live services, accounts, billing, browser, or end-to-end harness were exercised. Deployment, phone installation, permissions, provider availability, restart recovery and actual costs remain unverified.
- `S §3.1` through `S §3.6` refer to the six numbered requirements under “Locked Feature Requirements” in Rev 3 of `2026-10-28-t3-max-code.md`; `P1` refers to `2026-10-28-t3mc-max-page.md`. Both supplied documents were read from `/Users/owner/AgentWork/t3mc-docs/docs/superpowers/` (specs and plans respectively); they are not present in this checkout.
- `O:` paths resolve against the old-MAX commit above, in [max-launch-site](https://github.com/AnthonyHinojosa77/max-launch-site/tree/ebf305e07cd2c8b01958084b7f7e5ce15527a021). Other paths resolve against the T3MC baseline in [t3code](https://github.com/AnthonyHinojosa77/t3code/tree/dd5163e199a1385e2181b06a2c0d025cb2aea8ec). Line numbers are pinned to those revisions.
- `M/` abbreviates `apps/web/src/components/max/`; `G/` abbreviates `packages/max-gateway/src/`. “none” means no equivalent was found in the inspected MAX components, routes and gateway, not proof of absence everywhere in upstream T3.
- Recommendations are proposals, not newly approved requirements. “Fix now” means a concrete gap in the already requested behavior; it does not authorize E3 to modify code or the fixed Council API. “Later plan” on a Present row means retain it in subsequent integration validation, not defer its implementation.

## Scope reconciliation

[Slice B's recorded omissions](https://github.com/AnthonyHinojosa77/t3code/pull/14) are explicitly covered above: speech/read-aloud, upsells, per-card abort, latency badges and inline history expansion. A builder's slice omission does not establish Anthony's approval to drop an old feature. Personal-mode billing suppression is explicitly required by S §3.1; public-mode incompleteness is therefore recorded separately.

Old MAX's `src/` components, hooks, stores and services, every backend route file, README and mobile-readiness documents were inspected. The mobile-readiness documents contain historical claims that conflict with the later code: for example `backend-contract.md:348` says synthesis has no backend endpoint, while `packages/backend/src/routes/synthesis.ts:129` implements it. Current pinned code takes precedence; README “working” claims were not treated as live verification. The old native app is explicitly a placeholder. No export/share UI was found. Legacy direct-provider adapters are not counted as a second user feature: the reachable query path is `src/hooks/useModelQuery.ts` → `src/services/backendQuery.ts`.

Only the document is changed. The per-slice validation is `corepack pnpm fmt:check docs/operations/max-parity.md` and `git diff --check`; code tests, lint and typecheck are not run for this Markdown-only change. No new code errors are introduced by a code diff because there is no code diff; baseline lint counts and tests are not reasserted as freshly measured. The brief's known GuestPage failure is not a test result of E3.
